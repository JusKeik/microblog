# Corporate Microblog

Корпоративный микроблог: FastAPI, SQLAlchemy и PostgreSQL. Готовый Vue-интерфейс
и API обслуживаются одним приложением. Регистрация не предусмотрена:
пользователь определяется заголовком `api-key`.

## Запуск Docker Compose

Нужны Docker Engine / Docker Desktop и Docker Compose.
Из корня проекта выполните:

```sh
docker compose up -d --build
```

Также поддерживается команда из ТЗ `docker-compose up -d` при установленном
Compose v1. Последующие запуски: `docker compose up -d`.

- Сайт: http://localhost:8000
- Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка запуска: http://localhost:8000/health

Сервис API ждёт готовности PostgreSQL. Порт 8000 должен быть свободен.
Проверка состояния и журналов:

```sh
docker compose ps
docker compose logs -f api
```

Остановка: `docker compose down`. Твиты, пользователи, подписки и лайки
сохраняются в volume `postgres_data`; картинки — в `media_data`.
Не используйте `docker compose down -v`, если данные нужно сохранить:
флаг `-v` удаляет тома.

## Демо и использование

При первом запуске пустой базы создаются пользователи:

| Пользователь | API-ключ |
| --- | --- |
| Alice | `test-key-alice` |
| Bob | `test-key-bob` |
| Carol | `test-key-carol` |

Создаются подписки и два поста с разным числом лайков. Повторный запуск
не дублирует данные и не восстанавливает удалённые записи.
В ранее заполненную базу демо-посты автоматически не добавляются.

Откройте сайт. Новый браузер использует ключ Alice. Для переключения
пользователя введите ключ в отладочной панели и нажмите
«Установить новый api-key». Ключ сохраняется в localStorage браузера;
после перехода на страницу входа интерфейс автоматически проверяет его.
Старый сохранённый ключ `test` замените одним из ключей выше.
Поля логина и пароля не используются сервером.

Создайте пост, при необходимости приложите картинку. Для проверки подписок
откройте профиль другого пользователя, например `/profile/2`.
Лента содержит посты пользователей, на которых вы подписаны, и сортируется
по количеству лайков по убыванию, затем по дате и ID по убыванию.
Собственные посты не добавляются в эту ленту автоматически.
Кнопки готового интерфейса вне перечисленного ниже API (например,
редактирование профиля и твита) не входят в требования и не реализованы.

## API

Для всех `/api/` запросов нужен заголовок `api-key`. В Swagger нажмите
Authorize и введите демо-ключ.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/tweets` | Создать твит |
| DELETE | `/api/tweets/{id}` | Удалить свой твит |
| GET | `/api/tweets` | Лента подписок по популярности |
| POST | `/api/medias` | Загрузить картинку, multipart-поле `file` |
| POST / DELETE | `/api/tweets/{id}/likes` | Поставить / убрать лайк |
| POST / DELETE | `/api/users/{id}/follow` | Подписаться / отписаться |
| GET | `/api/users/me` | Собственный профиль |
| GET | `/api/users/{id}` | Профиль пользователя |
| GET | `/api/users/{id}/tweets` | Все твиты профиля, новые первыми |

Создание твита: JSON `{"tweet_data":"Первый твит","tweet_media_ids":[]}`.
`tweet_media_ids` необязателен; IDs получают из `/api/medias`.
Ответ: `{"result":true,"tweet_id":1}`, статус 201.
Загрузка возвращает `{"result":true,"media_id":1}`.
Остальные изменяющие операции возвращают `{"result":true}`.
Профили и лента соответствуют контракту ТЗ; ссылки вложений относительные.
Разрешены JPEG, PNG и WebP до 5 МиБ с проверкой сигнатуры и типа.
Чужие и уже прикреплённые медиа использовать нельзя.

Ошибки всегда имеют JSON-формат:

```json
{"result":false,"error_type":"unauthorized","error_message":"Invalid or missing API key"}
```

Основные статусы: 401 — отсутствующий/неверный ключ; 403 — запрет операции;
404 — объект не найден; 409 — конфликт или недопустимый файл;
422 — ошибка валидации; 500 — внутренняя ошибка без раскрытия деталей.
Схемы успешных ответов и ошибок доступны в Swagger.

## Разработка и проверки

Python 3.12+; PostgreSQL 16+. Создайте отдельную базу и пользователя.

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
```

Создайте `.env` с настройками своего PostgreSQL, например:

```dotenv
DATABASE_URL=postgresql+psycopg://microblog:microblog@localhost:5432/microblog
MEDIA_DIRECTORY=static/media
```

Запуск из корня проекта: `uvicorn app.main:app --host 127.0.0.1 --port 8000`.
Таблицы создаются автоматически при запуске; изменение существующей схемы
требует отдельной миграции. Текущий проект не меняет схему при старте.

```sh
pytest --cov=app --cov-report=term-missing
ruff check app tests
mypy app
```

Тесты используют изолированный SQLite в памяти и временную папку картинок.
Они не запускают основной lifespan и не меняют рабочую базу.
Проверены 30 тестов, покрытие 96%, Ruff и mypy без ошибок.
Отдельно проверены настоящий PostgreSQL и сохранность твита и изображения
после перезапуска процесса. Docker-сборка в текущем окружении не выполнялась:
Docker отсутствует. Production-образ не содержит тестовых зависимостей;
для dev-образа используйте `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build`.

Вкладка «Твиты» в профиле показывает собственные записи выбранного пользователя
независимо от подписок. Счётчик обновляется вместе со списком.
